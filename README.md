# Streaming Catalog & Viewing Behaviour – SQL Analysis

A self-contained SQL portfolio project: data cleaning, joins, aggregations, CTEs and window functions on a small streaming-service database (titles, users, viewing events).

> **Important – about the data:** All data in this repository is **synthetic**. It is generated by `data/generate_data.py` (fixed random seed, fully reproducible). It does **not** come from any real company, platform or training program. Numbers in `results/results.md` only demonstrate how the queries work – they are not real-world findings.

## Questions answered
1. How big is the catalog by type and genre?
2. Which genres get the most watch time (and what share of the total)?
3. How do monthly active users and watch hours change over a year?
4. What is the running total of watch hours per month?
5. Which genres have the highest completion rate?
6. What are the top 3 titles in each genre?
7. Does watch time differ by subscription plan?
8. How many users stay active for 1, 2, 3 … months?
9. Which countries have the most watch hours per active user?

## SQL skills demonstrated
- Data-quality checks: missing values, inconsistent text (case/spaces), duplicate rows
- Cleaning with a **view** (raw tables stay untouched): `TRIM`, `LOWER`, `CASE`, `ROW_NUMBER()` for de-duplication
- `INNER JOIN` / `LEFT JOIN`, `GROUP BY`, `HAVING`
- CTEs (`WITH`) and **window functions**: `RANK()`, running `SUM() OVER (ORDER BY …)`, share of total with `SUM() OVER ()`

## Project structure
```
data/
  generate_data.py      synthetic data generator
  titles.csv  users.csv  watch_events.csv
sql/
  01_schema.sql                      table definitions
  mysql_load.sql                     load CSVs into MySQL
  02_data_quality_and_cleaning.sql   checks + titles_clean view
  03_analysis.sql                    9 analysis queries
results/results.md      output of all queries
run_sqlite.py           runs everything offline (Python only)
```

## How to run
**Option A – no installation (Python 3):**
```
python run_sqlite.py
```
This builds an in-memory SQLite database, loads the CSVs, runs the cleaning and analysis scripts and rewrites `results/results.md`.

**Option B – MySQL 8+:**
1. Run `sql/01_schema.sql`
2. Run `sql/mysql_load.sql` (see the comment at the top about `local_infile`)
3. Run `sql/02_data_quality_and_cleaning.sql`, then `sql/03_analysis.sql`

To regenerate the data: `python data/generate_data.py`

## Notes on the data
- 412 raw title rows → 400 after removing 12 deliberately inserted duplicates
- Deliberate problems for the cleaning step: genre written in different case / with extra spaces, blank country and rating values
- ~44k viewing events over 2025 from 2,000 users
